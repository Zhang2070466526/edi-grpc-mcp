# 混频杂散分析说明

批量混频杂散分析：给定多个 Mixer + IF 候选点，枚举 `m×源频 ± n×LO` 的杂散组合，判断杂散频率范围是否与目标输出频带碰撞，返回通过的 IF 点与合并后的连续范围。

对应 MCP 工具 `analyze_mixer_spur`（`servers/rf_analysis/mixer_spur.py`）。

## 输入

### 批量分析入参（对应 MixerSpurAnalysisInput）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `mixers` | MixerSpurInput[] | — | 参与分析的 Mixer，可含未启用的（只算 `enabled==true` 的） |
| `if_candidates_mhz` | double[] | — | 主 IF 候选点（MHz，非空、升序） |
| `chart_if_candidates_mhz` | double[] | 空 | 图表扫描点（只收集通过点与范围，不存逐点明细） |
| `if_candidate_step_mhz` | double | 1.0 | 合并主通过范围的步长（MHz） |
| `chart_candidate_step_mhz` | double | 1.0 | 合并图表范围的步长（MHz） |
| `max_order` | int | 1 | 最大杂散阶次：`m+n ≤ max_order`，`m,n ≥ 0`，排除 `m=n=0` |
| `direction` | enum | receive | `receive`（源=RF、输出=IF）/ `transmit`（源=IF、输出=RF） |
| `require_all_mixers` | bool | true | 多 Mixer 判定：`true`=全部通过才通过、`false`=任一通过即通过 |
| `maximum_detail_count` | int | 12 | 保留明细的候选点数（`<0`=全部、`0`=不保留） |

### 单个 Mixer（对应 MixerSpurInput）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `name` | str | — | 标识，不参与计算 |
| `enabled` | bool | true | `false` 时跳过 |
| `relation` | enum | 随 `direction`：receive=`low_side`、transmit=`sum` | 变频关系（见下） |
| `rf_center_mhz` | double | 1000.0 | RF 中心频率 |
| `rf_bandwidth_mhz` | double | 0.0 | RF 带宽（构造 RF 范围） |
| `if_bandwidth_mhz` | double | 1.0 | IF 带宽（构造每个候选 IF 的范围） |
| `rf_power_dbm` / `lo_power_dbm` | double | −10 / 7 | 仅界面展示，**不参与**碰撞计算 |

> 上表"默认"列即缺省值：字段没传就按默认值补全，补了哪些字段会在返回的 `warnings` 里逐条列出（不会静默）。
> `relation` 缺省随 `direction` 走（receive=`low_side`、transmit=`sum`，与 C++ GUI 切方向后的默认项一致）；
> 显式传错（接收只有 `low_side/high_side`、发射只有 `sum/diff_lo/diff_if`）才 `INVALID_PARAMETERS`。
> 校验口径：`rf_center_mhz` 必须 **> 0**，带宽允许 0（单频点），`enabled` 必须是**布尔值**。
> `enabled=false` 的 Mixer 放宽校验（非法字段回落到默认值），避免陪葬整批分析。

**relation 与 LO 中心频率**：

| 方向 | relation | LO 中心 |
|---|---|---|
| 接收 | `low_side` | `RF − IF` |
| 接收 | `high_side` | `RF + IF` |
| 发射 | `sum` | `RF − IF` |
| 发射 | `diff_lo` | `RF + IF` |
| 发射 | `diff_if` | `IF − RF` |

## 输出

### 批量结果（对应 MixerSpurAnalysisResult）

| 字段 | 说明 |
|---|---|
| `valid` / `error` | 整体流程是否完成 / 失败原因（`valid==true` 不代表有通过点） |
| `direction` / `require_all_mixers` | 入参快照 |
| `enabled_mixer_count` | 启用 Mixer 数量 |
| `if_candidates_mhz` | 入参快照 |
| `passed_if_candidates_mhz` | 通过的主 IF 候选点 |
| `passed_if_ranges_mhz` | 合并后的连续范围 `[[起,止],...]` |
| `candidate_results` | 逐点明细（受 `maximum_detail_count` 限制） |
| `chart_passed_if_candidates_mhz` / `chart_passed_if_ranges_mhz` | 图表扫描的通过点 / 范围 |
| `warnings` | 仅在有字段按默认值补全时出现，逐条说明「mixers[i] 未提供 X，按默认值 Y 计算」 |

### 逐点明细（IfCandidateResult / MixerSpurResult / SpurCollision）

- `IfCandidateResult`：`if_center_mhz` + `passed` + `mixer_results[]`。
- `MixerSpurResult`：`lo_center_mhz` + `passed` + `error` + `collisions[]`；`passed = error 空且 collisions 空`。
- `SpurCollision`：`m` / `n` / `sign` / `min_mhz` / `max_mhz`，对应 `m×源频 + sign×n×LO` 的杂散范围。

## 算法流程

1. 校验 `max_order`、候选点、步长；
2. 筛 `enabled==true` 的 Mixer（没有则整体失败）；
3. 对每个 IF 候选点：算 RF/IF 上下边界 → 按 relation 算 LO → 枚举 `(m, n, sign)` → 排除目标混频产物本身 → 对 RF/IF 边界 4 角算杂散绝对范围 → 与目标输出频带（接收=IF、发射=RF）做重叠判断；
4. 按 `require_all_mixers` 汇总候选点是否通过；
5. 用 `if_candidate_step_mhz` / `chart_candidate_step_mhz` 合并连续通过点成范围。

**目标混频产物排除**（`isDesiredMixingProduct`）：`m=n=1` 时——接收排除 `sign=−1`（\|RF−LO\|）、发射 sum 排除 `sign=+1`（IF+LO）、发射差频排除 `sign=−1`（\|IF−LO\|）。

## 注意事项

1. 频率/带宽统一 **MHz**，调用前完成 Hz/kHz/GHz 换算。
2. `if_candidates_mhz` / `chart_if_candidates_mhz` 必须**严格升序**且不含重复点——`merge_ranges` 不自行排序去重，所以乱序/重复会直接返回 `INVALID_PARAMETERS`，不会静默给出错误的范围。
3. `valid==true` 只表示流程完成，**有没有通过点看 `passed_if_candidates_mhz` 是否为空**。
4. 单个 Mixer 的错误（负 LO、频率范围无效）在对应 `MixerSpurResult.error` 里，不使整体 `valid` 变 `false`。
5. `rf_power_dbm` / `lo_power_dbm` 不参与碰撞计算，别误当杂散幅度/功率判定输入。
6. ⚠️ **本工具算法层是 `mixerspuranalyzer.cpp` 的逐行移植，以 C++ 为准**：`absoluteRange` 会把 `±X` 折成同一区间，
   所以 `m=0,n=1`（LO 自身泄漏）时 `sign=+1` 与 `sign=-1` 会各出一条 `min_mhz/max_mhz` 完全相同的碰撞明细。
   **这是 C++ 原版行为，不要"去重"、不要改成只留一条**（`tests/test_rf_tools.py::test_spur_lo_leakage_reported_for_both_signs_like_cpp` 锁着）。
   同理：`analyzeMixer` 对 `relation` 与 `direction` 不匹配只返回 `-1.0` LO → 单 Mixer 报 `目标变频关系产生了负 LO 频率`（`valid` 仍为 true），
   MCP 封装层额外做的前置校验（缺省补全、relation 匹配、严格升序、`rf_center_mhz>0`、`enabled` 布尔）属于**界面约束的补充**，不改算法结果。
