# Win7 frozen dependency set (route E) -- KEEP THIS FILE PURE ASCII.
#
# WHY ASCII: pip 23 (bundled with Python 3.10) reads -r files with the Windows
# ANSI code page (GBK on zh-CN) when the file has no BOM. A UTF-8 Chinese comment
# makes pip die inside pip/_internal/utils/encoding.py:
#     UnicodeDecodeError: 'gbk' codec can't decode byte 0x80 ... in auto_decode
# (The dev box hides this: CPython builds with utf8_mode=1, PythonWin7 has
#  utf8_mode=0. Same file, different result.) Chinese rationale lives in the
#  repo docs: docs/WIN7*.md (deployment plan / downgrade feasibility).
#
# WHY THESE PINS (verified 2026-09-11 on CPython 3.10.20, 403 tests green,
# 98 extensions statically clean for Win7):
#   pydantic-core >= 2.28 is built with Rust >= 1.78, whose std hard-imports
#   bcryptprimitives!ProcessPrng (Win10 1809+) plus WaitOnAddress /
#   GetSystemTimePreciseAsFileTime (Win8+). On Win7 that fails at import with
#   "DLL load failed ... the specified procedure could not be found" (WinError
#   127) and installing UCRT / VC++ runtime does NOT help.
#   Measured clean ceilings: pydantic-core 2.27.2, rpds-py 0.18.1, mcp <= 1.12.4
#   (mcp 1.13.0+ already requires pydantic>=2.11 = over the line).
#   cryptography is also Rust and is not needed at runtime -- do not install it.
#
# INSTALL:       scripts\setup_win7_env.bat
# AFTER INSTALL: python scripts\patch_mcp_win7.py   (fixes mcp<=1.12.4 Context bug)
# DO NOT: upgrade mcp / pydantic / rpds-py, and do not install from pyproject.toml.
